# Первый результат в Kanysh Basic

[English](GETTING_STARTED.md) · [Сайт](https://kanysh.com)

Инструкция для геологов и инженеров по разработке месторождений. Сначала откройте
сохранённый пример Norne, затем проверьте свою модель. В подключённом чате можно
описывать задачи обычными словами.

У Kanysh Basic две части: **чат** запрашивает расчёты; **локальный просмотрщик**
показывает модели, отчёты и файлы. Расчёты и массивы модели остаются на вашей станции.
Какие сообщения и результаты инструментов получает AI-провайдер, определяет ваш чат-клиент.

Это development-сборка. Численный код и локальные подключения через SDK проверены.
Установка в реальный Claude Desktop, работа с реальными внешними чат-клиентами и
проверка нативной Windows/NVIDIA остаются **NOT RUN — не выполнены**. На первом этапе
может понадобиться помощь IT при установке из исходников. Для Windows используйте [нативную установку](INSTALL_WINDOWS.ru.md). Для CPU-сценариев Basic видеокарта не требуется.

## 1. Установите один раз

### Подготовьте компьютер

| Ваш компьютер | Где выполнять команды ниже |
|---|---|
| macOS | В приложении Terminal. Выбранный клиент Claude устанавливается отдельно. |
| Windows | Используйте [нативное расширение MCPB](INSTALL_WINDOWS.ru.md) без терминала и WSL. Команды ниже предназначены для macOS/Linux; установку из исходников на Windows ИТ-служба выполняет через PowerShell с Windows-путями. |
| Linux | В терминале. Используйте Claude Code или другой совместимый MCP-клиент; setup не регистрирует нативный Claude Desktop в Linux. |

**Скачайте ZIP исходников со страницы проекта на GitHub или из релиза и распакуйте.**
Если доступен `kanysh-basic-github-source.zip`, это очищенный архив исходников.
Найдите внутреннюю папку, где лежат `pyproject.toml`, `uv.lock` и `README.md`.
Страница README в браузере сама по себе не устанавливает программу.

Установите **uv** — утилиту, которая загружает Python и зависимости проекта,
по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
Если команда не найдена, закройте и заново откройте терминал. Проверьте:

```bash
uv --version
```

**Ожидаемый результат:** номер версии. Затем перейдите в распакованную папку проекта:

```bash
cd "/path/to/kanysh-basic"
```

Замените `/path/to/kanysh-basic` на настоящий путь, сохранив кавычки. Это путь установки из исходников на macOS/Linux; при необходимости попросите IT найти папку.
Не вводите пример пути без замены.

### Установите программу и подключение

Выполняйте команды по одной из этой папки:

```bash
uv python install 3.12
uv sync --frozen --no-dev --extra ui --extra viewer --python 3.12
```

Первая команда подготавливает Python 3.12, вторая устанавливает Kanysh Basic
и просмотрщик. Для первой установки нужны интернет и несколько ГБ свободного места
под научные библиотеки, дополнительно к месту под модели. Дождитесь возвращения
приглашения терминала. Если команда завершилась ошибкой, сначала найдите её в таблице ниже.

Закройте клиенты Claude и выполните:

```bash
uv run --no-sync kanysh-basic --home "$HOME/.kanysh-basic" setup
```

**Ожидаемый результат:** setup выводит сведения о настройке и открывает просмотрщик
с заголовком **Kanysh Basic**. Если браузер не открылся, используйте адрес из результата setup.
Статус просмотрщика `RUNNING` или `ALREADY_RUNNING` означает успешный запуск.
`CONFIGURED` или `UNCHANGED` относится к записи настроек клиента и ещё не доказывает
подключение чата. Перед изменением существующего файла настроек создаётся резервная копия.

Папка `$HOME/.kanysh-basic` хранит проекты и результаты. Продолжайте использовать
этот же каталог. Если у вас уже есть установка с другим каталогом состояния,
сохраняйте прежний `--home`, чтобы не открыть пустую папку. [Технические подробности](ONBOARDING.md).

### Если вам передали расширение Desktop

Файл `.mcpb` — пакет расширения, а не геологическая модель. Текущий
`kanysh-basic-0.2.0-dev3.mcpb` требует клиент с поддержкой UV runtime из MCPB v0.4.
Архив и запуск через SDK проверены; установка в реальное приложение Desktop —
**NOT RUN**. Нативная Windows включена в пакет; реальная приёмка остаётся NOT RUN. См. [установку Windows](INSTALL_WINDOWS.ru.md). Если клиент его отклоняет,
используйте установку из исходников выше или помощь IT. Не переименовывайте файл
ради установки. [Подробнее о расширении](ONBOARDING.md#desktop-extension-package).

## 2. Откройте Norne перед своими данными

В просмотрщике нажмите **Open Norne demo**. Дождитесь загрузки сцены.
Должен открыться проект Norne с 3D-сеткой, окрашенной по пористости. В списке
**Artifact and revision** выберите сохранённый `calculation_report` и откройте страницу результата.

**Ожидаемый результат:** 113 344 ячейки, из них 44 927 активных. В сохранённом отчёте
три ВНК 2585,5 / 2618,0 / 2693,3 м дают три разных значения STOIIP.
Кнопка открывает готовые результаты и не запускает новый расчёт. Параметры флюидов —
условия публичного теста, а не оценка запасов Norne.
[Точные числа и сценарий нового расчёта](DEMO.md).

## 3. Убедитесь, что чат подключён

Перезапустите клиент Claude после настройки. В новом разговоре напишите:

> Вызови инструмент start у Kanysh Basic. Покажи его приветствие и доступные проекты.

Если клиент предлагает серверные prompts — готовые запросы, можно выбрать **begin**.
Само слово «begin» в сообщении не доказывает вызов инструмента.

**Ожидаемый результат:** клиент показывает настоящий вызов инструмента Kanysh Basic
и возвращённые данные. Если вместо этого он объясняет продукт общими словами или
говорит, что инструмент недоступен, сначала восстановите подключение. Kanysh Basic
должен быть виден в списке подключённых инструментов клиента. В Claude Code подключения
можно проверить командой `/mcp`.

Чат и просмотрщик — разные окна. В просмотрщике нет собственного чата и форм запуска
расчётов. После установки названия инструментов нужны агенту; вы описываете задачу.

## 4. Добавьте и проверьте свою модель

Выгрузите копию модели из Petrel/RMS в отдельную папку. Для первой проверки сетки
предпочтителен полный **ECLIPSE ASCII DATA/GRDECL** со всеми INCLUDE-файлами,
геометрией, маской активных ячеек и свойствами. Сохраните структуру папок.
Нативная папка проекта Petrel/RMS не является такой выгрузкой.
[Какие объекты и форматы выгружать](PETREL_EXPORT.md).

В просмотрщике нажмите **Add folder** и выберите папку с данными. Так владелец
локальной установки разрешает к ней доступ. Кнопка сама не импортирует и не рассчитывает модель.
Затем напишите в чате:

> Изучи зарегистрированную папку модели. Перечисли файлы, недостающие данные
> и доступные проверки. Покажи источник предлагаемых параметров. Пока не считай.

**Ожидаемый результат:** сводка файлов и доступных сценариев либо явное описание
недостающих данных и ограничений сканирования. Это ещё не QC модели.

Сверьте предложенные систему координат, вертикальную привязку, единицы, направление
глубины/Z и определение регионов с документацией своего проекта. Если чего-то не знаете,
сообщите об этом: агент должен запросить данные, а не придумать их. Значения из файлов
становятся принятыми допущениями только после вашего подтверждения. Затем запросите:

> Я проверил и подтверждаю перечисленные параметры импорта. Импортируй модель
> и проверь геометрию и свойства. Покажи серьёзность проблем, ячейки IJK, сводки
> по регионам, допущения и результаты независимых проверок. Сохрани все замечания,
> не исправляй модель автоматически.

Подтверждайте только действительно проверенные параметры. **Ожидаемый результат:**
завершённое задание и QC-отчёт либо понятная ошибка/запрос недостающих данных.
Статус **ISSUES** означает замечания для разбора, а не разрешение удалить отмеченные ячейки.

## 5. Рассчитайте сценарий и сохраните отчёт

Для объёмов нефти/газа задайте выбранные регионы, ВНК/ГНК, Bo/Bg, основу насыщенностей,
единицы и вертикальную привязку — по требованиям сценария. Значения из демо Norne
не являются параметрами по умолчанию для вашего месторождения. Начните с запроса:

> Подготовь расчёт нефти и свободного газа по регионам этой модели. Сначала запроси
> все необходимые контакты, параметры флюидов и допущения. Считай только после моего подтверждения.

Проверьте и подтвердите свои входы, затем напишите:

> Выполни подтверждённый сценарий, независимо проверь результат и покажи таблицу
> по регионам с допущениями. Выгрузи расчётный и QC-отчёты в Excel и PDF.

**Ожидаемый результат:** реальное завершение задания, отчёт и ссылки на файлы экспорта.
Если просмотрщик запущен, ссылки на отчёт/сцену ведут в него. Откройте страницу результата
и сохраните XLSX/PDF по файловым ссылкам. Ответ чата без результата инструмента не подтверждает расчёт.

| Что вы видите | Значение и действие |
|---|---|
| Задание `succeeded` | Операция завершена. Отдельно прочитайте научные и QC-статусы отчёта. |
| Независимые проверки `PASS` | Численные проверки согласуются в пределах допусков. Геологическая интерпретация всё равно требует вашей экспертизы. |
| `ISSUES` | Разберите проблемы, их серьёзность и IJK. Не удаляйте ячейки скрытно. |
| `NEEDS_INPUT` | Уточните недостающие инженерные данные. Не подставляйте произвольное число. |
| `NOT RUN` | Проверка не выполнялась. Это не PASS и не нулевой результат. |

## 6. Продолжите работу позже

Используйте тот же клиент и каталог состояния. Если просмотрщик закрыт,
откройте терминал в установленной папке проекта и выполните:

```bash
uv run --no-sync kanysh-basic --home "$HOME/.kanysh-basic" setup
```

Команда использует работающий просмотрщик или запускает его. Если чат потерял
подключение, перезапустите клиент. Проекты хранятся в каталоге состояния, а не в разговоре чата.
Для постоянного/ручного запуска сервиса IT может использовать [настройку MCP](MCP_SETUP.md).

## Если что-то не получилось

| Проблема | Что сделать |
|---|---|
| Команда `uv` не найдена | Заново откройте терминал после установки. На Windows для исходной установки используйте PowerShell; обычная установка расширения не требует терминала. |
| Не найден `pyproject.toml` | Вы находитесь не в той папке. Найдите внутреннюю распакованную папку проекта и повторите `cd`. |
| Зависимости не устанавливаются | Проверьте интернет, свободное место, Python 3.12 и корпоративный доступ к пакетам. Сохраните текст ошибки для IT. |
| Просмотрщик не открылся | Возьмите URL из setup. При `FAILED` откройте указанный `viewer.log`. Порт может отличаться от 8765. |
| Setup показывает `STARTING` | Немного подождите и снова откройте указанный URL. Если страница недоступна, посмотрите указанный `viewer.log`. |
| Чат не видит Kanysh Basic | Перезапустите клиент, проверьте MCP-подключение. Конфликт настроек разбирайте по [технической инструкции](ONBOARDING.md). |
| Проекты выглядят пропавшими | Проверьте, используется ли тот же `--home`: у другого каталога состояния свой список проектов. |
| Не работает **Add folder** | Нужны локальная сессия владельца и диалог рабочего стола. На сервере без рабочего стола IT может использовать `source-add`. |
| Модель не загружается | Проверьте формат выгрузки, INCLUDE-файлы и отчёт импорта. Бинарные EGRID/ROFF сейчас ограничены 2 млн ячеек; большой блочный импорт использует ASCII. |
| Агент спрашивает CRS, datum или Bo/Bg | Предоставьте основу из документации проекта. Это требование к входам, которое нельзя обходить. |
| Задание завершилось ошибкой | Сохраните job ID и ошибку/отчёт. Не выдавайте последний успешный сценарий за результат этого запуска. |

Для воспроизводимого сообщения об ошибке укажите ОС, способ установки, операцию/job ID
и обезличенный текст ошибки. Уберите личные пути, ключи и конфиденциальные модели.
Удобство инструкции для независимых инженеров пока не проверено.
