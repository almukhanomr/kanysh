# Установка Kanysh Basic на Windows

[English](INSTALL_WINDOWS.md) · [Сайт](https://kanysh.com)

Для **Windows x64 и Claude Desktop**, поддерживающего MCPB 0.4 с UV runtime.
Проверка статических моделей и расчёт объёмов работают нативно: **WSL не нужен**.
Демо Norne включено в расширение. При первой установке нужен интернет для загрузки
Python 3.12 и научных библиотек; загрузка может быть значительной.

**Приёмка нативной Windows-версии, установки зависимостей через Claude Desktop и
NVIDIA — NOT RUN.** Проверка разрешения Windows-зависимостей не заменяет установку.
Картинки ниже — иллюстрации инструкции, а не скриншоты проверенной установки Windows.
До выполнения списка приёмки в конце документа нельзя обещать проверенный релиз
«в один клик».

## 1. Скачайте и откройте расширение

Установите или обновите [Claude Desktop](https://claude.ai/download). На странице
[релизов проекта](https://github.com/almukhanomr/kanysh/releases) скачайте
`kanysh-basic-0.2.0-dev1.mcpb`, **если этот файл приложен к релизу**.
Архив исходного кода GitHub — другой файл. Дважды нажмите на `.mcpb`.
Если Windows не открывает его в Claude, используйте установку локального расширения
в настройках Claude. Названия пунктов зависят от версии клиента.

![Скачивание MCPB — иллюстрация](images/windows-1-download.svg)

## 2. Нажмите Install и выберите папки

Папка результатов по умолчанию — **`%LOCALAPPDATA%\kanysh-basic`**. Оставьте её,
если ИТ-служба не указала другую локальную папку. В поле **Model folder (optional)**
выберите папку с выгрузкой Petrel/RMS, например `D:\Geology\FieldA`.
Вы разрешаете чтение только этой папки. Можно подключить её позже кнопкой
**Add folder** в просмотрщике. Снимки входных данных и результаты занимают место
в папке результатов; исходные файлы модели не изменяются.

Нажмите **Install** и дождитесь загрузки зависимостей. Не закрывайте Claude во время
установки. До установки Python расширение ещё не может показывать собственный статус:
ход загрузки и ошибки смотрите в окне или журнале установки расширения Claude.
После запуска Python в папке результатов появляются `startup.log` и
`startup-status.json`. Статус `MCP_READY` означает готовность сервера ждать клиента;
успешное подключение Claude подтверждает только реальный вызов инструмента.
Ошибки просмотрщика находятся в `viewer.log`.

![Выбор папок и Install — иллюстрация](images/windows-2-install.svg)

При первом успешном запуске просмотрщик откроется в браузере. Если этого не произошло,
используйте адрес из журнала запуска. Это локальный адрес вашего компьютера.

## 3. Получите первый результат

Напишите в Claude:

> Вызови инструмент start Kanysh Basic. Покажи подключённые папки и оцени папку модели.
> Скажи, чего не хватает. Перед импортом попроси подтвердить единицы, CRS и высотную систему.

Убедитесь, что Claude действительно вызывает инструменты и получает результаты.
В просмотрщике **Open Norne demo** открывает готовые демонстрационные результаты.
Для собственной модели сначала изучите импорт и QC. Перед расчётом нужно подтвердить
контакты, Bo/Bg, насыщенности и выбор регионов.
[Подготовка выгрузки Petrel/RMS](PETREL_EXPORT.md) ·
[Как читать результаты](GETTING_STARTED.ru.md).

![Первый запрос и просмотрщик — иллюстрация](images/windows-3-start.svg)

## Если установка не получилась

- **Клиент не поддерживает расширение:** обновите Claude Desktop. Нужна поддержка
  MCPB 0.4 и `server.type=uv`. [Спецификация](https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md#uv-runtime-v04).
- **Ошибка загрузки, прокси или сертификата:** передайте ИТ-службе журнал установки
  Claude. Библиотеки загружаются с PyPI и официального CPU-индекса PyTorch.
  Политика рабочей станции должна разрешать Python, UV, просмотрщик и загрузку пакетов.
- **Ошибка запуска:** откройте `%LOCALAPPDATA%\kanysh-basic\startup.log` и `viewer.log`,
  либо такие же файлы в выбранной папке результатов. Не прикладывайте конфиденциальные
  модели и учётные данные к обращению в поддержку.
- **Папка отклонена:** выберите настоящую папку NTFS без символических ссылок,
  junction-точек и перенаправлений. После замены папки её нужно подключить заново.
  Для букв диска, пробелов, кириллицы и регистра добавлены нативные тесты.
  Очень длинные пути зависят также от настроек Windows/файловой системы; при ошибке
  используйте более короткий путь.
- **В релизе ещё нет файла:** ИТ-служба может собрать его из установленного исходного
  проекта командой `uv run --no-sync python scripts/build_mcpb.py` и передать вам `.mcpb`.

## GPU NVIDIA — опционально, для ИТ-службы

Расширение по умолчанию устанавливает **CPU-сборку PyTorch**. Блочный импорт и анализ
копилота используют CPU; установка CUDA не ускоряет все операции. Приёмка GPU остаётся
**NOT RUN**. Нужен драйвер NVIDIA, совместимый с выбранной сборкой CUDA 12.8.
[Инструкция PyTorch](https://pytorch.org/get-started/locally/).

Для GPU используйте отдельное окружение исходного проекта. Расширение не меняет
драйверы и не переключает ускоритель автоматически. В PowerShell, из папки проекта
с установленным `uv`:

```powershell
uv python install 3.12
uv sync --frozen --no-group cpu --extra gpu --extra ui --extra viewer --python 3.12
uv run --no-sync kanysh-basic --home "$env:LOCALAPPDATA\kanysh-basic-gpu" doctor
```

`cuda_available=true` означает обнаружение устройства, а не приёмку расчётов.
CPU-группа и GPU extra взаимоисключающие. При дальнейшей синхронизации сохраняйте
`--no-group cpu --extra gpu`; обычный sync вернёт CPU-профиль. Для подключения этого
окружения вместо расширения сначала отключите расширение и запустите setup с отдельной
папкой результатов. Конфликты регистрации нужно разобрать явно.
Выбор индексов ускорителя рассчитан на `uv`, а не обычный `pip`.
[Настройка PyTorch в uv](https://docs.astral.sh/uv/guides/integration/pytorch/).

## OPM Flow через WSL — опционально

**Linux/WSL нужен только для гидродинамического симулятора.** На нативной Windows
инструменты запуска симуляции возвращают `SOLVER_PLATFORM_UNSUPPORTED` с пояснением.
Extra `solver` устанавливает `resdata` только на Linux. Экспорт дека не означает
запуск OPM Flow. Статические расчёты остаются нативными.

Для гидродинамики ИТ-служба готовит отдельную установку Linux/WSL с выбранной сборкой
OPM Flow, extra `solver` и своей папкой результатов. Не используйте одну SQLite-папку
одновременно из Windows и WSL. См. [поддерживаемые профили](SUPPORTED_PROFILES.md).
Полная приёмка OPM Flow остаётся **NOT RUN**.

## Приёмка Windows-релиза — только по фактическим результатам

1. Установить именно этот MCPB на чистую Windows x64 через Claude Desktop; записать
   версию клиента, SHA-256 пакета и результат установки зависимостей.
2. Оставить LocalAppData и выбрать настоящую папку NTFS. Проверить открытие просмотрщика,
   source_list/folder_assess, кириллицу и пути с буквой диска.
3. Открыть Norne, выполнить новый импорт/QC/сценарий, проверить отчёт, сохранить XLSX/PDF.
4. Запустить Windows CPU pytest: один владелец, отмена/таймаут с дочерними процессами,
   замена корня, запрет junction и длинные пути. Записать явные пропуски.
5. Перезапустить Claude и проверить сохранение проектов; NVIDIA проверить отдельно,
   если требуется. Манифест и разрешение зависимостей не заменяют NOT RUN на PASS.
