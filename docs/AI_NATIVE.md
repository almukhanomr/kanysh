# MCP-first продукт

Kanysh Basic — AI-копилот для расчётов по геологическим моделям рядом с Petrel/RMS.
Архитектура: MCP server for subsurface modeling + local web viewer.
Основной интерфейс инженера — внешний MCP-клиент. Собственного чата, голосового сервиса,
провайдерских SDK и ключей генеративных моделей в сервере нет.

Клиент формулирует задачу, уточняет научные входы и вызывает typed tools. Сервер проверяет
аргументы, доступ к данным, единицы и ресурсы, выполняет инженерный код и сохраняет результаты.
Модель не подменяет расчётные библиотеки и независимую численную проверку.

## Процесс

1. `kanysh-basic setup` создаёт home, сохраняет резервные копии настроек Claude и открывает просмотрщик.
2. Владелец подключает папку кнопкой «Add folder» или `source-add`; у MCP нет инструмента расширения доступа.
3. `start`/prompt `begin` объясняет демо и собственные данные; `folder_assess` находит роли и недостающее.
4. Найденные EQUIL/PVT/единицы/CRS — только предложения с файлом/строкой. Агент запрашивает подтверждение ДО плана/расчёта.
5. `eclipse_import`/`geodata_import`/`grid_import` закрепляют модель и входы; `model_qc` показывает дефекты с severity/IJK.
6. Через `regional_volumes`, `volumes_reconcile`, `wells_vs_model`, `model_diff`, `sensitivity_tornado`, `uncertainty_monte_carlo` запускаются явные расчёты. Все входят в профиль agent.
7. `job_status` даёт фактическое состояние; отчёты содержат независимые проверки и ограничения.
8. `results_export` сохраняет XLSX/PDF. PASS экспорта означает проверку файла; статусы источника сохраняются.
9. `result_preview` выдаёт изображение либо JSON/resources. Активный просмотрщик добавляет `viewer_url`.

Прежний сценарий построения через `calculation_plan` сохраняется: `NEEDS_INPUT` при недостатке
данных, закрепление runtime/входов, `calculation_run`, checkpoints и `report_export`.
Пять MCP prompts описывают вопросы и шаги для QC, региональных объёмов, сверки, торнадо и сравнения версий.

Пример: «Сравни объёмы по трём ВНК с этими свойствами и Bo, проверь результат, покажи
неопределённость по пористости и сохрани отчёт». Все допущения остаются явными.
STOIIP — начальный объём нефти; скалярная неопределённость не заменяет пространственные реализации.
Geological fitness остаётся `REQUIRES_REVIEW`.

## Просмотрщик и данные

Extra `[ui]`, команда `serve --ui`: проекты/ревизии, готовые отчёты, `scene_export` HTML,
сейсмические срезы, загрузка файлов и офлайн-демо Norne. Научных форм, чата и записи аудио нет.
Extra `[viewer]` нужен для экспорта PyVista/trame сцены worker-процессом, а не для чтения HTML.
Размер превью ограничен; расчёты используют полную поддерживаемую модель.

Viewer links ведут на защищённые `/viewer/projects/.../artifacts/...`, не содержат credentials
и не рекламируются при остановленном просмотрщике. Typed id/revision refs не изменяются.
Самодостаточные HTML и MCP resources доступны независимо от UI.

Сетки и кубы не передаются AI целиком: tools выдают summaries, refs, ограниченные изображения и отчёты.
Клиент определяет отправку сообщений и tool results своему AI-провайдеру. Сервер хранит SHA-256,
immutable revisions, runtime fingerprint, jobs/attempts и проверки. Текст файлов — данные, не инструкции.

## Граница продукта

Локальное ядро, MCP/CLI/REST и необязательный просмотрщик входят в основной продукт.
Runpod находится в локальном `experimental/runpod` (Advanced, исключён из GitHub-публикации Basic), не входит в пакет,
production tools и обязательную приёмку. A-10 — **«заменено MCP-клиентами»**.
Windows/WSL2/NVIDIA, реальный OPM и внешние OAuth-клиенты требуют отдельной проверки.
[ACCEPTANCE](ACCEPTANCE.md), [PETREL_WORKFLOW](PETREL_WORKFLOW.md).
